# 厂商甲：网页驱动 HID 协议（结构层面）

> 厂商甲 = 采用"网页驱动"方案的某国产手柄厂商（通过浏览器 WebHID 配置/识别设备）。
> 本文只描述我们**逆向得到的帧格式结构**，不出现任何可被反查到真名的字符串，
> 也不包含任何闭源程序二进制或源码。

## 一、识别方式

厂商甲的网页驱动通过浏览器 `navigator.hid` 与设备交互。设备识别条件包括：

- 特定 **VID / PID**（不同硬件型号对应不同 PID）。
- 特定 **usagePage**（厂商自定义用法页）。

> 工程提示：浏览器要求用户手势（点击）才能 `requestDevice`；但有些页面在加载后用
> `getDevices()` 自动附着已配对设备，此时不需要再次手势。

## 二、帧格式

主机（网页）与设备的通信帧为定长结构，头部 + 命令 + 长度 + 载荷 + 校验：

```
[ 0x5A ][ 0xA5 ][ cmd ][ len ][ payload… ][ checksum ]
```

- **cmd**：命令 id。例如设备信息、UUID、协议版本、SKU、槽状态、读 RAM 等。
- **len**：payload 长度（协议里的约定长度，例如 26 字节载荷 + 头部/校验构成 32 字节帧）。
- **payload**：按命令不同而异。
- **checksum**：`bytes[2 .. 末尾-1]` 的按字节累加和（取低 8 位）。
- **响应帧**：通常以 `pkgCount` / `pkgIndex` 表示分包；`pkgCount == 0` 表示错误；
  建议超时重试（例如 1500ms × 3 次）。

## 三、设备能力位

设备信息命令的末字节是**能力位图**，按位表示设备支持：IMU、LED、物理开关、屏幕、
扳机触觉、扳机振动、音频、强振动等。我们据此判断一台设备"能做什么"。

## 四、固件门槛（门禁的一种）

网页驱动在连接后会校验设备**固件版本**是否不低于一组按硬件型号设定的最小值；低于门槛
会被拒绝进入配置页。这些最小值可以从网页前端 bundle 里推出（不同硬件型号对应不同下限）。
绕过这层后，下一步才是真正的配置/引擎能力——后者往往没有公开下载渠道。

## 五、与传输层的关系

厂商甲的这套 5A/A5 帧，是"网页 → 设备"的直接配置通道；它和综述里描述的
"配置 blob → HID 报告"范式是同一回事，只是帧头与命令集不同。门禁（VID/PID/usagePage、
固件版本）都属于**枚举/握手层**，与配置 blob 的字段偏移无关。
