# 方法论：不跑程序也能还原手柄配置字段偏移

传统逆向手柄配置协议，往往要从闭源原生二进制里反编译、动态调试，既慢又依赖硬件。
本项目验证了一套**纯静态、零硬件**的替代路线，核心是把厂商自己的配置界面当成"协议说明书"。

## 背景：配置协议的两层

几乎所有带"力反馈扳机 / 自适应扳机"的手柄，都遵循同一套范式：

1. **配置界面层（UI）**：厂商的 PC 端配置程序（多为 Electron / Web）把用户的选择
   组织成一个**配置对象**，每个字段标注"占多少 bit"。
2. **传输层（HID）**：这个配置对象被**位域打包**成一个连续字节缓冲区（配置 blob），
   再通过 HID 输出报告下发到手柄。

关键洞察：**位域打包的规则就写在配置界面的源码里**。只要拿到 UI 层的
schema 对象 + 打包函数，就能在本地复刻它，直接算出每个字段在 blob 里的字节偏移——
完全不需要运行闭源程序，更不需要手柄硬件。

## 步骤

### 1. 提取配置界面（asar / 前端 bundle）

现代手柄配置程序大多是 Electron，资源打包在 `app.asar` 里。用 `asar extract`
（或自写的轻量 asar 解析器，注意 JSONC 尾部逗号与注释）把前端源码解出来。

### 2. 定位 schema 与打包器

在解出的源码里搜索配置对象的字段定义（通常每个键后面跟着注释 `占8bit` 之类），
以及负责把对象打包/解包进字节缓冲区的函数（典型命名含 `profile`、`pack`、`refresh`、
`raw`）。

### 3. 复刻位域打包逻辑

打包器的逻辑通常是：按 schema 声明顺序，逐字段把 bit 累加到全局游标，记录每个字段的
`[字节偏移, 字节数, 位偏移, 位宽]`。把这段逻辑用 Python 复刻，喂入同一份 schema，
即可得到全部字段的绝对偏移。

> 这一步的复杂度远低于反编译原生二进制：一个 1.6MB 的闭源 DLL 全量反编译要十几分钟，
> 而解析前端 schema 只要几秒。

### 4. 交叉验证

算出的 blob 总位宽，应当等于 UI 侧自己声明的"配置 blob 长度"（例如厂商乙声明 720 字节）。
两者吻合，即证明偏移还原正确。

## 适用边界

- 只还原"配置结构 / 字段偏移"，不还原任何闭源实现细节。
- 若厂商把打包逻辑混淆或放到原生层，则需结合原生二进制分析（本项目未涉及）。
- 设备门禁（VID/PID/usagePage 过滤）属于枚举层，不在本方法范围内，但同样可静态分析。
